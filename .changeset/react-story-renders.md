A test story now says why each React component rendered. With `@variance-authority/react/story` in the suite's setup files, every commit adds a line per component that rendered, at the step that caused it, a keyed one named with its key (`Row key="b"`): `rendered Summary — expanded false → true`, `rendered Cart — useState #0 false → true`, a class's `state`, a context by its display name, `mounted` once at the top of a subtree that mounts, `its parent rendered` when none of its inputs moved, `no input it reads moved` when the props object is the same one, or `state not read past <hook>` where the hook reader stops (`state not read` in a build that keeps no hook record). Where React loaded before the setup and will announce no commit, the story says `renders not read: react-already-loaded`. Values are shown as handed ones are, objects by their ref, and story compare leaves a ref's number out of every line, so comparing two tests' stories lists, at its step, each render line only one of them said. Where `@variance-authority/react/story` is in the setup files, Eyes leaves a commit to it and says no `eyes commit …` line: the render lines say which components committed, and why. `tapCommits` takes `onRender`, which hands over each component that rendered while its previous render is still on `fiber.alternate`. The story note channel takes a template — its strings and values — and shows each value as a step shows what it was handed.
