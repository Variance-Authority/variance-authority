`variance covering` reads the record `variance select` reads: in a checkout that has not recorded the suite, the mainline's at the merge base, fetched when this machine does not hold it, and the answer names that record with the same `record of "<suite>":` line, or `source` under `--format json`. When the share cannot be reached it answers from the record held here and says how far behind that is. `--since` lists what the change changed, from the merge base with `<ref>`, whatever the record holds of it: a change you committed and recorded is still your change, and `nothing has changed` means only that the merge base and the tree agree. The record's commit says how to read each file: a line stands on the line the record holds it at, a hunk from there is the change's where it meets one of the change's in the working tree, so one hunk both sides wrote is answered whole. A path the record's commit held no file by, added or renamed since, is listed with no row and says so, with `absentAt` under `--format json`, and `--file` with the name that commit held reads what it recorded. A ref that does not read as a diff is one `undiffed` refusal at exit 2, before any record is read, including under `--execution`; such a ref used to be answered from the record's commit. A record made at a commit this clone lacks names what to fetch. A `--text` question, which an editor asks on every repaint, reads the records in the same order and does not fetch. A record fetched for another mainline is not read for the one selected: the question falls to the primary checkout's record and says so. `--format refs` says whose record it read on stderr. `@variance-authority/sense/test-selection` exports `changeInRecord`, `ChangeRead` and `absentText`, `CoveringChange` carries `absentAt`, and `readableTestCoverage` takes `fetched: 'passed'` for a caller that turned the fetched record down.
