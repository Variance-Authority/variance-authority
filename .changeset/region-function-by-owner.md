A region of a journey answer names the function the record says it is written
in, not the smallest function on its first line: a branch of `submit` that
begins on the line of a callback `submit` passes is `submit`'s, where it was the
callback's. Each region of a record names the region that holds it, and
its function is the nearest function up those owners. A record written before
regions named their owners leaves the regions inside a function in none, and
each module of a `testsRan` answer says in `ownersNamed` whether its record
names them, so `docs_test_claims` says what a test passed by there is not
known rather than that it passed by nothing. On such a record `pathsThrough`,
`forksBetween` and a composition's `own` and `reached` show its functions with
no inner regions. There a one-line guard and its function are both innermost
on their line, so `passedAt` returns `unowned`, the region not entered, and
`beside`, the function entered, when the test entered the function and not the
guard: `ask grep --test` lists that line under "Not known". `resonance` refuses
such a line when the cases of the guard and its function differ.
`encodeAsSetExecutionIndex` takes those owners as its second argument.
`pathsThrough`, `forksBetween`, `testsRan`, `docs_test_claims`, the `passedAt`
of a story and `ask grep --test` read it.
