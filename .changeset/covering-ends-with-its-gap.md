`variance covering` ends an answer that leaves its question open with a gap: the question, the scope, what is known, the reason (`absent`, `stale` or `coarse`), the exact commands that close it, and how many tests in how many test files they run. A line held at file grain names the story of the three nearest tests (Deep). A record of another text, and lines written or ranges edited since the recording, name a recorded run of the test files (Record); a record older than the file names the test files it ran that import the file, and no record at all one recorded run of the suite. A suite given to the share is sent to `variance share --suite <name>` instead. The gap names the test files and cases to run, filtered by name with the runner's own filter, since no record names the runner. The gap is printed after the answer; under `--format json` it is the answer's `gap`, and it sits beside `refused` in a refusal. The skill's new `fsd` reference says which reading answers a question and what each gap asks you to run.
