A Vitest or Jest shard of a selected run now records the test files it ran and nothing else, as a shard of a whole run does: it lays no base under its run, selects from the record it was handed, and a shard that runs no file leaves no record. A shard handed no record reads the one its checkout holds, which `variance shards` priced. A shard that runs in passes, such as near tests and then far ones, selects and places each pass from the record it was handed, beneath what its earlier passes ran, so a later pass neither re-runs nor skips what the first one decided. A run is a shard by the runner's resolved `shard`, whether `--shard` or the runner's API, such as `startVitest` or Jest's `runCLI`, set it. A later pass runs only the files the record placed in its range: a test new since the recording, and every file of a selection that declined to narrow, runs in the first pass alone, so no file runs in two passes or lands in two shards. A seam reads that set from the new `only` field of `SuiteSelection`, which `kept` honours. `VARIANCE_AUTHORITY_PLACE_AT_DISTANCE` names the hops of every pass a shard runs, such as `0-`: each pass then places the files of all of them as one and runs its own of that shard's part, so its passes together take the part the plan priced rather than the heaviest part of each pass. Unset, a pass is placed alone. A seam reads that placement from the new `placing` field of `SuiteSelection` through `placed`, and `selectSuite` takes it as `placeAtDistance`. `variance share` folds the parts over that record, and a test file or case no shard ran keeps the row it had. Before, a selected shard laid its run over the base it was seeded with, so two shards each carried the other's base rows and the fold refused them.

`variance carry take <dir> --as-base` lays a pull request's last push where `carry receive` laid the mainline's read, for a shard: it selects from the record the plan counted, and its own record still holds only what it runs. It refuses to run before `carry receive`. `carry take <dir>` without it now re-bases each record it takes on a mainline published since the push, as reading it would, and writes those bytes back to `<dir>`, so a shard that takes the same directory reads the record the plan priced.

An upgrader whose shards carry a pull request's last push adds `--as-base` to the shards' `carry take`. A run that is not sharded records as before, and a `share` that folds shards reads the new records as it reads a whole run's.

The Jest selection reporter no longer reads a `selected` option. `withTestSelection` set it to tell a selected run's shards from a whole run's, and they now record the same way; a config that passes it by hand can drop it.
