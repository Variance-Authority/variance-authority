# Journal 0035 — The consequence survives the browser

**Date:** 2026-08-26

The hierarchy contract made the Underwriter relationship failure explicit while
the page was open, then lost it at the boundary of the ordinary regression run.
The run could retain changed pixels and call the CSS impact `layout`, but neither
record said that the edit introduced equal leading-to-body and body-peer spacing.

The first tempting route was appending presentation findings to the existing
single-render findings list. That preserved the condition and erased the edit:
an introduced collision, a resolved collision and one present on both sides all
became the same row. Reusing render impact was worse; it turned a consequence
into a property classification and invited policy to treat every layout change
as the same thing.

The durable value is now a fourth independent signal. A paired fixture carries
an introduced hierarchy collision, a reverse pair carries its resolution, and a
missing layout reading becomes incomparable. A product-owned hierarchy effect
retains its contract id. The CLI mapping also accepts the signal on an observation
with no document or pixel signal, which is the test that keeps independent
boundaries from becoming an all-or-nothing bundle.

The stored Underwriter-shaped example reports `outerMedianPx=4` and
`innerMedianPx=3.99` under `underwriter-demand-record`. The HTML and agent text
read those measurements from the report; neither asks the browser again or
changes the observation verdict.
