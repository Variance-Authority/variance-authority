The `variance-authority` skill says how to fill a gap an answer names, never by running the whole suite again over a record that exists. A suite with no recording takes `variance share --suite <name>` when the refusal names it, and otherwise one recorded run once its producer is wired. A test file or case runs with the runner's own filter. A source file the suite never loaded, or one the record is older than, takes `variance share` for `older` in a shared suite once the mainline has recorded the file; otherwise run the test files of that suite that `variance ask discover --to` finds importing it, or, in a suite that drives the code from another process, the specs for the page, route or story it serves. For `undiffed` it says to fetch the commit the base names, or ask without the base. The testing skill now says what a story shows: the values each function was handed — a number or a boolean as it is, a string quoted and cut to 40 characters, an object as a ref and its kind — what a module's top level declared, and what the code printed.
