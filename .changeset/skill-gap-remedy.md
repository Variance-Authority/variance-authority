The `variance-authority` skill says how to fill a gap an answer names, never by running the whole suite again over a record that exists. A suite with no recording takes `variance share --suite <name>` when the refusal names it, and otherwise one recorded run once its producer is wired. A test file or case runs with the runner's own filter. A file the record is older than is new: `variance reach --since <base>` takes every file the diff added at once, with no record. Lines written since the recording, in a file the record holds, run the test files that ran code in the file, which `variance covering --file <path> --format refs` lists. A file the suite never loaded runs the test files `variance ask discover --to` finds importing it. A suite that drives the code from another process runs the specs for the page, route or story the file serves. For `undiffed` it says to fetch the commit the base names, or ask without the base. Inside the edit loop, `VARIANCE_AUTHORITY_SINCE=` already selects what each edit reached. The testing skill now says what a story shows: the values each function was handed — a number or a boolean as it is, a string quoted and cut to 40 characters, an object as a ref and its kind — what a module's top level declared, and what the code printed.
