`variance covering` names why git could not give a file's text where a run stood, in git's words: a commit this clone does not hold, with the `git fetch` that brings it, a blob it lost, or a git-LFS pointer with no content here. Only that file at that commit is left open; every other file at the commit is still judged. Motion under `--cases last` lists such a module as not compared, with git's reason, rather than failing. `readTextsAt` returns the texts git read and its reason for each one it could not, by commit and file, and `readBlobsAt` the same for blob names without reading the texts. `blobsAt` fails naming a commit this clone does not hold, rather than answering every path at it absent.

When `variance select` runs every test because it cannot diff a commit tests last ran at, and the clone does not hold that commit, the note names the commit and the fetch that brings it, or `fetch-depth: 0` with `filter: tree:0`.
