`variance select` finds a changed file's rows in the native addon. The search over a recording's sorted paths, the test paths it reports, the preconditions it asks the record about and the names of the regions it charges are answered from the stored bytes, and each run of a column is decompressed once for as long as the recording is open. Whether a mock disowns a crossing asks whether the test mocks the file before it reads which tests crossed the block, and a column read again in the run it read last does not move that run to the back of its cache. Over this repository's unit suite one selection decodes 1.4 thousand strings in JavaScript instead of 84 thousand, reads 128 thousand column rows instead of 810 thousand, and `variance select --suite unit` takes 449 ms instead of 498 ms, with the same output.
