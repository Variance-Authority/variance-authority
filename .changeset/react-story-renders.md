A test story now says why each React component rendered. With `@variance-authority/react/story` in the suite's setup files, every commit opens with a `commit — <n> rendered` line, counting the components it rendered, `0` for one that rendered only host elements, `, started by Cart` where a development or profiling build recorded whose update started it, a keyed one with its key, and adds a line per component that rendered, at the step that caused it, a keyed one named with its key (`Row key="b"`), read through a keyed `memo` or fragment that wraps it, and `(hidden)` inside a hidden `<Activity>` or behind a Suspense fallback: `rendered Summary — expanded false → true`, `rendered Cart — useState #0 false → true`, a class's `state`, a context by its display name, `mounted with Badge, Summary` once at the top of a subtree that mounts, naming each component that mounted below it, `its parent rendered` when none of its inputs moved, `the Suspense boundary above it came back from its fallback` when the boundary retried it, `no input it reads moved` when the props object is the same one, or `state not read past <hook>` where the hook reader stops (`state not read` in a build that keeps no hook record). Where React loaded before the setup and will announce no commit, the story says `renders not read: react-already-loaded`. Values are shown as handed ones are, objects by their ref, and a value made anew each render says `(same source)` for a function written by the same source or `(equal value)` for a plain object or array equal in value, and story compare leaves a ref's number out of every line, so comparing two tests' stories lists, at its step, each render line only one of them said. Story compare counts a line said: one test that says a line twice and another that says it once read apart, `commit — 1 rendered ×2` against `commit — 1 rendered`, so an extra commit shows. Where `@variance-authority/react/story` is in the setup files, Eyes leaves a commit to it and says no `eyes commit …` line: the commit line and the render lines say which components committed, and why. `tapCommits` takes `onRender`, which hands over each component that rendered while its previous render is still on `fiber.alternate`. The story note channel takes a template — its strings and values — and shows each value as a step shows what it was handed.
